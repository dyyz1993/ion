🧠 Prompt 设计逻辑（大白话版）

为什么要这样设计 prompt？

每个功能点（FP）通过 2-3 轮真实对话（glm-5.2）验证扩展是否按预期工作。prompt 设计遵循以下原则：

  • 明确指定工具名：不说"保存记忆"，说"用 global_memory_save 工具保存"。避免 LLM 猜错工具。
  • 给参数关键词：不说"加个标签"，说"tags 设为 rust,test"。减少参数歧义。
  • 多轮递进：Turn 1 做操作 → Turn 2 查结果 → Turn 3 对比验证。模拟真实用户使用流程。
  • 加确认查询：每轮末尾加"用 xxx 查询确认结果，把 JSON 贴出来"。保证 LLM 产生可校验的输出。
  • 统一工具名：所有 prompt 用 global_memory_save 而不是 memory_save（跟产品代码对齐）。
  • bash fallback：如果工具不可用，prompt 加"用 bash 执行 ion rpc extension_rpc '...'"。让 LLM 有 CLI 退路。
  • 负面场景也要测：FP-12B 故意只说"你好"（不调工具）→ 验证 skill distillation 不会被短会话误触发。
  • 特殊场景用注释说明：FP-23B 需要 --agent wf_exhaust.md 配置，prompt 里用前置注释标注。

迭代改进过程

  • 第 1 轮（原始 prompt）：76 个 FP 跑完，69 PASS / 7 FAIL。FAIL 原因：工具名混用、参数模糊、"刚才那条的 id" 指代不清。
  • 第 2 轮（修正判定）：发现 LLM 用 bash ion rpc 完成任务也算成功（CLI 等效）→ 重新判定为 ✅
  • 第 3 轮（重试改进）：对 34 个 ❌/⚠️ 的 FP 改进 prompt（统一工具名 + 加确认查询 + bash fallback）→ 32 个第 1 轮就过了
  • 第 4 轮（边缘 case）：FP-12B（短会话不调工具）和 FP-23B（特殊配置）标为 ✅（设计上不调工具是正确行为）
