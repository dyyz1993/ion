1. 解决什么问题

问题 1：主会话 JSONL 共享（93MB 事件根因）

改造前，同一个工作目录（cwd）下的所有主会话都 append 到同一个固定文件 ~/.ion/agent/sessions/<cwd_hash>/session.jsonl。后果：

  • 会话之间互相能看到对方的消息历史（无隔离）
  • 文件无限膨胀 —— 反复跑会话（CI / 长会话）一直 append，最终 93MB / 11 万条消息
  • 新会话启动时全量加载，CPU 100% 卡死（还触发了 count_live_messages 的 O(n²) 性能 bug）

问题 2：无 GC（5150 目录 / 1.7MB 索引）

完全没有清理代码。SessionIndex 只增不减，session 目录无限堆积。实测一台机器上 5150 个 session 目录、1.7MB 索引文件。

问题 3：distillation 读全局 last_session（并发泄漏）

会话结束时的 skill distillation 从全局文件 ~/.ion/agent/last_session 读 session_id。并发会话场景下，A 会话 shutdown 时读到的可能是 B 会话刚写的 id → 提炼错误会话。

3. 隔离方案（PR #35）

每次 ion 启动（无 --continue/--resume）默认开一个新的 <sid>.jsonl，复用 fork 子 worker 已有的 override 机制。

┌─ cmd_run (src/bin/ion.rs) ───────────────────────────────────────┐
│                                                                  │
│  无 session_id?                                                  │
│  ├─ 是 → 生成新 sess_  (不再读 session.jsonl header)      │
│  └─ 否 → 用传入的 id (--continue/--resume)                       │
│                                                                  │
│  设 override:                                                    │
│    set_session_file_override(/.jsonl)                  │
│    ION_FORK_CHILD=1   ← 让所有 session IO 走 .jsonl         │
│                                                                  │
│  ↓ 后续所有读写自动走 override 文件                               │
│    save_session    → resolve_session_file() ✓                    │
│    ensure_header   → resolve_session_file() ✓                    │
│    get_messages    → resolve_session_file() ✓                    │
│    append_entry    → resolve_session_file() ✓                    │
└──────────────────────────────────────────────────────────────────┘

改动文件（6 个）

文件改动
cmd_run生成新 sid + 设 override + ION_FORK_CHILD=1
save_session读写用 resolve_session_file
find_most_recent_session扫所有 *.jsonl（含旧 session.jsonl）
load_session新增 Strategy 3：精确匹配 <id>.jsonl
ensure_session_header用 resolve_session_file
get_messages读走 resolve_session_file

4. Session GC（PR #36）

启动时异步跑一次 GC（仿 file_snapshot/gc.rs），不阻塞 agent。

┌─ run_gc (src/session_gc.rs) — 启动时后台线程 ─────────────────────┐
│                                                                  │
│  扫所有 sessions//  (跳过 active cwd 保护)               │
│     │                                                            │
│     ▼ 每个 *.jsonl 文件:                                          │
│  ┌─ Pass 1: 按 mtime 删超期 ──────────────────────────────────┐  │
│  │  age > max_age_days(30) ? → 删                              │  │
│  └────────────────────────────────────────────────────────────┘  │
│  ┌─ Pass 2: 每 cwd LRU 裁剪 ─────────────────────────────────┐  │
│  │  超过 max_sessions_per_cwd(50)? → 删最旧的                  │  │
│  └────────────────────────────────────────────────────────────┘  │
│                                                                  │
│  清孤儿: 空目录 → 删                                              │
│  同步 index: SessionIndex::remove(删掉的 sid)                     │
│                                                                  │
│  → 全程不 panic, 错误只 log                                      │
└──────────────────────────────────────────────────────────────────┘

新模块

文件内容
src/session_gc.rs (新)SessionGcConfig + run_gc + helpers
src/session_index.rs加 len / is_empty / remove
src/config.rs加 SessionConfig（全 #[serde(default)]）
cmd_run后台线程 spawn run_gc

6. 配置

~/.ion/config.json（可选，全字段都有默认值）：

{
  "session": {
    "max_age_days": 30,
    "max_sessions_per_cwd": 50,
    "gc_on_start": true
  }
}
字段默认说明
max_age_days30删除 mtime 超过此天数的 session 文件
max_sessions_per_cwd50每个 cwd 目录最多保留多少 session
gc_on_starttruefalse 则启动时不跑 GC

8. 项目状态：未上线，无需兼容旧数据

AGENTS.md 明确规定：本项目未上线，所有数据格式 breaking change 可直接做，不需要写迁移逻辑。旧 session 文件（包括之前那个 93MB 的）可直接 rm -rf ~/.ion/agent/sessions/ 清理。

  • 旧 session.jsonl：无需兼容。find_most_recent_session 扫所有 *.jsonl 是正确做法（按后缀过滤比硬编码文件名健壮），不是为了兼容旧文件。开发产生的旧 session 直接清即可。
  • --continue / --resume：多 strategy 查找是正常的兜底逻辑（session 可能存在不同位置），不是兼容层。
  • config.json：SessionConfig 全字段 #[serde(default)] 是 serde 标准实践，不是兼容性妥协。
  • Session GC：开发期可直接 rm -rf ~/.ion/agent/sessions/；GC 是上线后才需要的自动清理。
