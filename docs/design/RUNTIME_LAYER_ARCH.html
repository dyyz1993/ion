② Runtime 层 — 可整体切换的「手脚」
FileSystemCapability（ctx.fs 门面）
RuntimeFileSystem 持有 Arc<dyn Runtime>， 所有扩展文件读写委托 Runtime 路由；外加 allowed_roots 白名单 + safe_join 防 ../ 逃逸。
read_file write_file list_dir path_exists glob
Runtime trait + BackendRegistry（路由器）
每次调用逐条决策去哪个后端：先查 routes（命令前缀 / 路径 glob 命中）→ 未命中走 default。 worker spawn 时读配置，改配置新会话即生效（host 无需重启）。
execute_command read_file / write_file / edit_file / rm spawn_processRemote 后端不支持（返回 Err）

⚠️ 已实测的 remote 语义边界：命令前缀不剥离（整条原样发远程）· 本地 cwd 不转发（远端跑在远端 HOME）· Windows cmd 对端文件工具必挂（cat/heredoc POSIX 假设）· 后台进程不支持。

切换方式 = 改配置（三种粒度）

// ~/.ion/config.json → runtime 段
{
  "backends": {
    "win38":  { "type": "remote", "hostname": "win38", "user": "sshuser", "port": 22 },
    "nas":    { "type": "remote", "hostname": "192.168.0.103", "user": "root" }
  },
  "default": "local",                    // ① 全局默认（可整体切 remote）
  "routes": [                              // ② 按命令前缀分流
    { "tool": "bash", "command": "ffmpeg-hevc *", "target": "win38" },
    { "tool": "write", "path": "/private/tmp/*", "target": "nas" }  // ③ 按路径 glob 分流
  ]
}
经过 Runtime 层（随切换走） 绕层强制本地（不随切换） remote 后端（SSH，win38 实测 ✅） 配套机制
