# Goal Supervisor 深化计划 — 目标校正 + 实时监控 + 诊断 agent

## 核心理念

当前系统只判"完成没有"（硬判定）。深化后增加**"进展好不好"**（软分析）+ **"不好怎么办"**（校正 + 诊断）。

三层递进：
```
第 1 层：进展分析（on_gate_check 里加，不调 LLM，纯启发式）
  → 判断：收敛 / 振荡 / 偏离 / 停滞
  → 输出：ProgressReport（附加到 RetryWith 消息里）

第 2 层：目标校正（goal_refine tool，LLM 可调）
  → 进展分析发现问题时，RetryWith 消息建议 agent 调 goal_refine
  → goal_refine：增量改检测项 / 调整 objective（不覆盖整个 goal）

第 3 层：诊断 agent（goal_diagnose tool，可选，重度场景）
  → 进展严重偏离时，spawn 一个专家 agent 读日志深度诊断
  → 返回校正建议（拆分目标 / 换模型 / 放宽检测）
```

## 任务 1：进展分析（ProgressReport）

**改动文件**：`src/goal_supervisor_extension.rs`

新增 `analyze_progress()` 方法，在 `on_gate_check` 里调用（每次 gate 检查后、RetryWith 之前）：

```rust
pub struct ProgressReport {
    pub trend: ProgressTrend,       // Converging / Oscillating / Drifting / Stagnant
    pub failed_history: Vec<Vec<String>>,  // 最近 K 轮的 failed_checks
    pub recommendation: String,     // 给 agent 的建议
}

pub enum ProgressTrend {
    Converging,    // failed 在减少 → 健康
    Oscillating,   // failed 数不变但元素在变 → 撞墙，建议 refine
    Drifting,      // action plan 跟 objective 不相关 → 跑偏
    Stagnant,      // failed 完全不变 K 轮 → 卡住
}
```

**分析逻辑**（纯启发式，不调 LLM）：
1. 读 iterations.jsonl 最近 3 轮的 failed_checks
2. Converging：failed 集合在缩小（3→2→1）
3. Oscillating：failed 数量不变但元素变化（如 [A,B]→[B,C]→[A,C]）
4. Stagnant：failed 完全相同 3 轮（已有 repetitive guard 部分覆盖，但这个更精准）
5. Drifting：用 calculate_similarity 对比 action plan 和 objective 的关键词重叠度

**集成点**：`on_gate_check` 的 RetryWith 分支，把 ProgressReport.recommendation 追加到消息里：
```
"Goal not complete. Failed: [...]
 Progress analysis: {trend}. Recommendation: {recommendation}.
 Fix the failing checks."
```

## 任务 2：目标校正（goal_refine tool）

**改动文件**：`src/goal_supervisor_extension.rs`

新增 `GoalRefineTool`（共享 SharedGoalState，跟 GoalSetTool 一样）：

```rust
pub struct GoalRefineTool(pub SharedGoalState);

// execute 支持：
// - objective_patch: Option<String>（更新目标描述）
// - checks_add: Vec<Check>（加检测项）
// - checks_remove: Vec<String>（按 name 删检测项）
// 保留 iteration_count / started_at / total_cost_usd（不清零进展）
```

**跟 goal_set 区别**：goal_set 覆盖整个 goal（清零进展），goal_refine 增量改（保留进展）。

**集成**：在 ProgressReport 的 recommendation 里，当 trend=Oscillating/Drifting 时建议"consider calling goal_refine to adjust checks"。

## 任务 3：诊断 agent（goal_diagnose tool）

**改动文件**：`src/goal_supervisor_extension.rs` + `examples/agents/goal-diagnostician.md`

新增 `GoalDiagnoseTool`——当进展严重偏离时，agent（或 RetryWith 消息）可以调这个 tool spawn 一个诊断 agent：

```rust
pub struct GoalDiagnoseTool {
    pub state: SharedGoalState,
}
// execute: 拿 &dyn Runtime，spawn_worker(agent="goal-diagnostician", 
//   task=打包 objective + failed_checks + iterations 日志, wait=true)
// 返回诊断 agent 的分析结果
```

**诊断 agent**（`examples/agents/goal-diagnostician.md`）：
- 读 goal-runs 日志
- 分析失败模式（3 维度：检测项质量 / agent 能力 / 目标可行性）
- 返回建议（拆分目标 / 换模型 / 放宽检测 / 终止）

## 任务 4：实时偏离监控（on_tool_execution_end）

**改动文件**：`src/goal_supervisor_extension.rs`

在 `on_tool_execution_end` 钩子里追踪 agent 行为：
- 维护 `recent_tools: Vec<(tool_name, args_summary)>`（滑动窗口 K=10）
- 检测：连续 K 次 bash 但没 write/edit 目标文件 → drift signal
- drift 时在 on_gate_check 里把信号加入 ProgressReport

## 实现顺序

1. **任务 1（进展分析）** — 核心价值最高，纯启发式零 LLM 成本
2. **任务 2（goal_refine）** — 让 LLM 能动态调整
3. **任务 4（偏离监控）** — 补充实时信号
4. **任务 3（诊断 agent）** — 重度场景可选

## 测试

- 单元测试：ProgressTrend 各分支（Converging/Oscillating/Drifting/Stagnant）
- 单元测试：GoalRefineTool 增量改（保留 iteration_count）
- e2e：FauxProvider 模拟 Oscillating 场景，验证 RetryWith 里带 recommendation
- 真实 LLM：验证 agent 看到 recommendation 后会调 goal_refine

## 不改的

- 不改 Extension trait（用现有钩子）
- 不改 agent_loop（gate 触发点不变）
- 不改 goal_evolver（事后分析保持独立）
