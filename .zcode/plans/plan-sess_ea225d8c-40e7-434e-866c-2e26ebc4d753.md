# 合并 `ion-worker` 到 `ion`：单一二进制方案（v2 — 含使用场景对比 + CI 验证）

## 核心问题

场景 2/3 的 host 引擎 spawn worker 子进程时找 `ion-worker` 二进制。但 worker 本质就是"`ion` 在 RPC 模式下运行"，不需要是另一个文件。这是历史遗留，对齐 PI 的 `pi --mode rpc` 设计。

## Part A: 10 个核心使用场景 — 改造前后对比

> 命令前缀 `ion` / `ion-worker` 是用户/CI 直接敲的；host 内部 spawn worker 是间接的（用户看不到）。

## Part C: 实施步骤（代码改动）

### C.1 抽 lib 模块（机械搬运，不重构）

- `src/bin/ion_worker.rs` (4958 行) → `src/worker_rpc.rs` (lib 内)
- `async fn main()` → `pub async fn run_worker_rpc(args: WorkerRpcArgs) -> Result<(), anyhow::Error>`
- 内嵌的 struct（`ManagerBridge`、`McpProxyTool`、`StreamingExtension`、`WorkerAgentRpc`、`FsProbeExtension` 等）+ 单元测试一起搬
- **保持三个 static 全局**（`SESSION_FILE_PATH/SID/CWD`）——最小改动，验证通过后再清理

### C.2 改 ion.rs 入口

```rust
// src/bin/ion.rs line 3223-3228 改为：
if matches!(cli.mode, Some(OutputMode::Rpc)) {
    let args = ion::worker_rpc::WorkerRpcArgs::from_cli(&cli);
    ion::worker_rpc::run_worker_rpc(args).await?;
    return;
}
```

删除 `cmd_mode_rpc`（line 1349-1362）+ 删除 `src/rpc.rs`（1370 行过期代码，无 production 调用方）。

### C.3 改 spawn 点

```rust
// src/worker_registry.rs line 243-270 简化为：
let worker_bin = std::env::current_exe()
    .map_err(|e| e.to_string())?;
let worker_bin = if worker_bin.exists() {
    worker_bin
} else {
    which::which("ion").map_err(|e| e.to_string())?  // fallback
};
```

Args 不变（已有 `--mode rpc`）。Env vars 不变。

### C.4 Cargo.toml

```toml
# 删除：
[[bin]]
name = "ion-worker"
path = "src/bin/ion_worker.rs"
```

## Part D: 风险与缓解

| 风险 | 缓解 |
|---|---|
| `src/rpc.rs` 删除可能漏调用方 | grep 全仓只有 `cmd_mode_rpc` 一处调用；`unit_rpc_test.rs` 实际 spawn 的是 `ion-worker`（即 ion_worker.rs），不依赖 `src/rpc.rs` |
| 抽 lib 时 borrow checker 问题 | 优先保持 static + struct 原样搬运，不做重构 |
| CI 脚本批改遗漏 | sed 后用 B.3 的验证项 #8 grep 确认 0 残留 |
| `current_exe()` 容器内失效 | 保留 `which::which("ion")` fallback |
| 内嵌测试搬到 lib 后路径变化 | 测试用相对路径/`CARGO_MANIFEST_DIR`，不依赖 bin 位置 |
