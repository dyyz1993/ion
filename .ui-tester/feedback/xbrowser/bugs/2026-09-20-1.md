# xbrowser bug #1
- 命令: `xbrowser --session <brand-new-session> goto "http://192.168.0.38:15180/#sessions"`
- 严重度: P2 不符预期

## 复现
1. 全新 session（daemon 冷启动）执行 goto，目标是带 hash 的 SPA 页面
2. 报错 `Navigation failed: waitForLoadState('domcontentloaded') timeout after 30000ms`（复现 2 次，两次都是新 session 首个 goto）
3. 但紧接着 `title` 返回 "ION Web"、`session list` 显示该 session url 已是目标 URL、eval 正常执行 —— **导航实际成功了**

对照：老 session（orch，已跑过 20+ 条命令）的 goto 从未出现此超时。

## 预期 vs 实际
- 预期：domcontentloaded 在页面加载早期即触发，goto 应成功返回；若真失败，session 不应有正确的 url/title
- 实际：新 session 首个 goto 30s 超时报失败，但页面已加载成功（假阴性），自动化脚本会误判环境故障并重试

## 源码定位（只读分析，不改代码）
- 疑点方向：新 session 创建 → daemon/CDP 连接建立 → goto 的 wait loadState 时序存在竞态；或 goto 前页面处于 about:blank，domcontentloaded 监听注册晚于事件触发导致永久等待直至超时
- 建议：goto 超时后先 probe `document.readyState`/title，若已就绪则返回成功（降级为 warning），避免假阴性
