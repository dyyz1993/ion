# xbrowser bug #2 (2026-08-30)

- 命令: `xbrowser --session s "goto url && wait '#x' && eval '(()=>{const a=1;if(a)return 1})()'"`
- 严重度: P2 不符预期 (chain 内 eval 语义被破坏, 静默产出错误 JS)

## 复现
`xbrowser --session s "click '#b' && eval '(()=>{const ov=1;if(ov)return 1})()'"`
→ 实际执行的脚本是 `(()=>{const ov=1 if(ov)return 1})()` — 分号被剥掉, SyntaxError: Unexpected token 'if'

## 预期 vs 实际
- 预期: 引号内的 eval 表达式原样传递
- 实际: chain 分词器把 `;` 当命令分隔符剥离, 即使它位于单引号字符串内部; 报错信息还回显被截断的脚本, 易误判为自己写错

## 源码定位（只读分析，不改代码）
- 文件: chain 解析模块 (chain parser), 分号 split 在引号感知之前执行
- 根因/建议方向: split 前做引号状态机; 或 eval 子命令在 chain 内改用 base64 传递
